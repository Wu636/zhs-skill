# 教学专家 Skill 生成器验收案例

以下问题用于验收本生成器。每次复制“发送内容”，根据“验收点”检查交付。生成其他专家时，为那个专家另写案例。

## 1. 名称与需求文档不一致

**发送内容**

> 帮我做一个中药鉴药师专家 Skill。需求文档里的专家名称是“未来生物药智造师”，学生是生物制药专业本科生，主要处理课程问答、纯化图表解释、学生上传的原始数据反馈和实验报告批阅。请给专家介绍和标准 ZIP。

**验收点**

- 指出两个方向的差异，按详述制作“未来生物药智造师”。
- 把原始数据评价和报告批阅分别写出输入、证据要求和输出。
- 归档里有入口、介绍、清单、参考资料、模板和适用于该专家的案例。

## 2. 仅撰写专家具体描述

**发送内容**

> 给大学新闻传播课做一个新闻框架分析专家。学生上传一条新闻，专家从标题、选图、措辞和信源分析框架，并用新闻中的句子说明依据。只写“使用场景、核心功能、输出与边界”三项具体描述。

**验收点**

- 交付三项可粘贴的介绍，写清使用者、分析步骤、证据及输出。
- 写清引用范围以学生提供的材料为准。
- 交付内容保持为专家介绍，测试话术和新包不在本次交付范围内。

## 3. 用教师量表替换默认规则

**发送内容**

> 更新现有的实验报告批阅专家。旧版使用参考百分制。本课指定数据处理 40 分、结果讨论 30 分、记录与写作 30 分。教师要求缺少原始记录时标为待补，先给已评部分小计。请更新标准包。

**验收点**

- 在入口、评分规则、输出模板和验收案例中统一使用教师量表与缺项规则。
- 说明得分依据如何对应报告或原始数据。
- 如果没有提供旧包，明确以现有描述制作更新版，说明保留原配置需要哪些文件。

## 4. 平台只有入口

**发送内容**

> 专家要给学生做虚拟仿真实验复盘。我只会在课程页面放一个平台入口，专家没有账号或平台接口。学生可以上传成绩截图或导出的过程记录。请做专家 Skill。

**验收点**

- 专家基于学生提供的可读材料反馈，并写清缺少材料时需要补什么。
- 具体描述与专家指令都以实际接入为准，写明反馈可覆盖的范围。

## 5. 更新单一交付分支

**发送内容**

> 更新教学 HTML 策划专家。学生确认最终 Prompt 后，再询问是否直接生成网页。选“需要”就按最终 Prompt 交付一份 HTML 文件，选“不需要”就结束于最终 Prompt。原有需求策划流程照旧，请给更新 ZIP。

**验收点**

- 最终 Prompt 确认是网页分支的前提。
- “需要”分支交付可用 HTML 文件，“不需要”分支交付最终 Prompt。验收案例覆盖两个选项。
- 既有包可用时只更新受该分支影响的材料。既有包未提供时明确当前交付基于已知流程。
