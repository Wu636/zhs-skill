# 作业批阅技能生成器

## 目标与固定交付

把一组课程材料沉淀为一个课程专用批阅 skill。每次必须交付：

1. **批阅名称**：面向教师的短标题；
2. **批阅描述**：说明批阅对象、证据格式、评分结构、样本校准与输出；
3. **学生提交作业要求**：可直接粘贴到教学平台，清楚区分必交、可选和二选一格式；
4. **作业批阅 skill ZIP**：严格采用用户提供的批阅模板，包含单一根目录及 `README.md`、`SKILL.md`，并按需包含 `references/`、`scripts/`；不加入模板之外的 `agents/`、`assets/` 或产品配置文件。

若用户同时要求“把生成方法沉淀为 skill”，除课程专用包外，再交付本生成器或其更新版 ZIP。不得把学生原始样本、姓名、学号、教师分数文件名或无关个人信息打进课程 skill。

开始前读取：

- [references/material-and-calibration.md](references/material-and-calibration.md)：材料优先级、样本覆盖、教师分数回归与防泄漏；
- [references/platform-contract.md](references/platform-contract.md)：作业批阅模板、score/evaluations 和包结构；
- [references/delivery-checklist.md](references/delivery-checklist.md)：学生要求写法、验证、自测和交付清单。
- [references/template-readme.md](references/template-readme.md)：生成到每个批阅 skill 根目录的模板结构说明。

若环境提供 `skill-creator`，先读取其 SKILL.md，使用其命名、frontmatter 和验证原则。用户提供专用批阅模板 ZIP 时，以该模板的平台目录和字段契约为最高结构标准；`skill-creator` 自动生成的模板外文件不进入最终批阅 ZIP。

## 工作流

### 1. 盘点材料，不急于设计分数

先设置共享绝对技能根与独立运行目录。以下 `RUN` 必须替换为当前项目/用户指定的真实绝对路径，禁止把占位传给脚本；课程材料、状态、临时产物、解压目录与 ZIP 均放在技能安装树外，不得落入 `~/.agents/skills` 或其他共享代码树。配置、登录态与运行数据仍按应用/用户隔离，不随技能共享。

```bash
SKILLS_ROOT="$HOME/.agents/skills"
BUILDER="$SKILLS_ROOT/assignment-grading-skill-builder"
RUN='<项目中的绝对运行目录>'
mkdir -p "$RUN/tmp" "$RUN/zips"
python3 "$BUILDER/scripts/inventory_materials.py" "<课程材料目录>" --output "$RUN/tmp/material-inventory.json"
```

识别：题目要求、评分表、教师说明/截图、教师已评分或分档样本、学生普通样本、参考答案、格式模板和技术附件。对 DOCX/PDF 逐页渲染核对；对图片查看原图并用 OCR 辅助；对音频/视频完整听看或按课程规则抽样；对表格保留公式、批注和隐藏工作表信息。纯文本提取只用于检索，不足以替代视觉/听觉审阅。旧版 `.doc` 报告可尝试用 `qlmanage -o <dir> -p <file>.doc` 提取预览附件；若有图片输出，须对照原文核对数量、分辨率与内容完整性，不能默认已取全原图，未核实部分列为待复核（`textutil` 转文本会丢图，而数据往往只在照片里）；各类格式的取证命令与失败形态见 [references/material-and-calibration.md](references/material-and-calibration.md) 第 8 节。

目录名中的“优秀/中等/较差/95分”等，在**构建阶段**可作为教师标签记录；在生成后的课程 skill 批阅新学生时必须被隔离，不得从路径标签反推分数。

### 2. 建立规则来源与冲突表

先写一张内部矩阵：`规则事项 | 用户最新说明 | 权威文档 | 旧文档 | 样本表现 | 最终采用 | 理由`。优先级为：

1. 用户/教师对当前歧义的最新明确说明；
2. 标为完善版、最终版或当前版的题目与评分文件；
3. 教师明确给出的分数、等级和评语；
4. 其他课程材料；
5. 样本中可重复观察的质量特征；
6. 通用领域经验。

样本不得推翻明确题目要求。例如未来必交模块暂未出现在历史样本中，仍应保留该模块和分值，只把它标记为“暂无样本校准，按量表评分”。

### 3. 建立“成果 - 格式 - 必交性 - 分值 - 证据”矩阵

逐项确认：

- 学生要交什么成果；
- 每项必交、可选，还是 PDF/PNG 等二选一；
- 支持的文件格式及重复格式如何归并；
- 每项分值、分档描述、缺项规则和封顶/统一扣分；
- 评分所需证据位置与读取方法；
- 哪些模块存在教师样本，哪些模块只使用权威量表。

- 若权威要求未规定文件格式，学生提交要求采用宽容、可读、便于平台上传的表达，不擅自新增页数、字数、命名或录制要求。若同一内容只需提交 PDF 或 PNG 中一种，要明确写“任选一种”，不写成两份都交。
- 课程材料没有给出的限差、阈值、检核较差，写成“内部参考口径”并与原文限差分开放，且只对明显超限判扣分、临界值进复核（写法见 [references/material-and-calibration.md](references/material-and-calibration.md) 第 9 节）。把自定数值写成“课程要求”会让教师无法复核扣分依据。

### 4. 匿名化分析教师样本并建立校准锚点

遵循 [references/material-and-calibration.md](references/material-and-calibration.md)：

1. 构建阶段允许读取教师分数/等级；
2. 逐样本记录实际覆盖模块与可观察证据；
3. 把姓名、学号、题目细节和原始文件名移除，只保留匿名质量特征；
4. 数值分数样本建立目标分布和允许分差；等级样本建立对应模块档位；
5. 未覆盖模块不做样本推断；
6. 区分“正式 100 分结果”和“历史样本覆盖模块回归”，缺项不会被覆盖归一化掩盖。

样本校准的是教师尺度，不是让技能记忆样本答案。任何“只要标题类似/文件名含分数就给对应分数”的规则都不得进入成品。

### 5. 设计可复核的课程批阅 skill

优先使用 `dimension`，维度一般不超过 10 个，分值和为 100；固定题目逐项评分可使用 `item`，整体档位才使用 `gradient`。先把用户模板解压到临时目录，移除模板附带的 `.DS_Store`，将模板根目录重命名为 skill 的 `name`，再按 [references/platform-contract.md](references/platform-contract.md) 写：

- 根目录只保留模板允许的 `README.md`、`SKILL.md`、按需使用的 `references/` 和 `scripts/`；
- `README.md` 使用 [references/template-readme.md](references/template-readme.md) 的结构说明；
- frontmatter 的 `name` 使用小写连字符，description 说明批阅对象、参考标准、评分和评价范围；
- `SKILL.md` 写输入、工具/脚本、完整取证流程、评分表、缺项/封顶/扣分、JSON 输出和审计；
- 长量表、校准锚点和格式细节放 `references/`，并在主文件明确何时读取；
- 只有确定性、可复用的操作才放 `scripts/`，脚本帮助盘点、抽帧、转码、核对合计或打包，不替代专业评分；
- `SKILL.md` 必须按模板顺序包含“批阅对象”“批阅流程”“1. 评分项（score）”“2. 评价项（evaluations）”；
- 输出的每个分数都有证据，`total` 与分项合计一致；
- 同一问题只扣一次，除非权威题目明确规定跨模块影响；
- 材料受限时列“人工复核”，不把未确认事实写成错误。

仅当环境中已确认 `skill-creator` 的 `init_skill.py` 实际存在且可用时，才按其真实路径辅助初始化，且只借用 frontmatter 和目录命名能力，不猜测脚本路径；缺失时直接按用户模板组织目录并使用本包 `validate_grading_skill.py` 验证。临时解压与生成目录均放在 `$RUN` 内；打包前移除模板外的 `agents/`，最终批阅包仍以用户模板为准。

### 6. 生成学生提交作业要求

学生文本必须是“做什么 + 交什么 + 怎么交 + 关键质量要求”，语言直接、无评分内部术语。按此顺序组织：

1. 一句话任务目标；
2. 编号列出必交成果；
3. 单列可选成果；
4. 说明允许格式和二选一关系；
5. 提醒文件可打开、页面/音频完整、链接有效、来源和 AI 使用按题目注明；
6. 如多个文件，给出合并或 ZIP 建议，但不擅自增加教师未规定的硬性命名规则。

不得把“历史样本校准”“模块权重调整”“人工复核”等内部批阅逻辑写给学生。

### 7. 静态验证与回归自测

先运行：

```bash
python3 "$BUILDER/scripts/validate_grading_skill.py" "$RUN/<课程 skill 目录>"
```

仅当已确认 `skill-creator` 的 `quick_validate.py` 实际存在且可用时，才按其真实路径补充验证；缺失时使用上述本包验证器，不编造路径。验证器还应确认顶层没有 `agents/`、`assets/` 或其他模板外项目。随后执行：

- 满分样例、典型中档、典型低档各 1 次；
- 每个必交成果缺失 1 次；
- 每种等价格式各 1 次，例如 PDF-only 与 PNG-only；
- 有教师数值样本时逐个盲测：评分模型看内容、不看路径分数，比较教师分与模型分；
- 只有等级样本时，检查其实际覆盖模块是否落入对应档位；
- 暂无样本模块按权威量表做合成边界测试，不伪造教师锚点；
- 检查高分评语是否与高分一致，低分是否有具体证据，是否存在重复扣分。

默认目标：数值样本平均绝对误差不高于 5 分、单个分差尽量不高于 8 分；用户另有阈值时采用用户阈值。调优只修改有证据的锚点、权重或归因，保留权威分值和必交性。

### 8. 打包与交付

先清理 `.DS_Store`、`__MACOSX`、`__pycache__`、`.pyc`、临时渲染和原始学生样本，再运行：

```bash
python3 "$BUILDER/scripts/package_skill.py" "$RUN/<课程 skill 目录>" --output "$RUN/zips/<课程 skill 名>.zip"
```

解压到临时目录复查：ZIP 只有一个根目录；根目录名与 `name` 一致；`SKILL.md`、本地引用和脚本均存在；没有 TODO、占位文本或隐私文件。最后以固定四项格式交付，并附可点击 ZIP 路径。

## 输出格式

最终答复按以下结构，内容齐全且简洁：

```text
批阅名称：...

批阅描述：...

学生提交作业要求：
...

作业批阅 skill：<zip 文件>
```

若同时交付生成器：另加 `作业批阅 skill 生成器：<zip 文件>`。不要只给目录而漏掉 ZIP，也不要只给 ZIP 而漏掉前三项文本。
