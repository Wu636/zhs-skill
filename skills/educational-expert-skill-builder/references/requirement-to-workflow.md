# 从需求到专家工作流

## 提取需求

| 需求项 | 对生成结果的影响 |
| --- | --- |
| 专家名称、使用人群和典型场景 | 确定对外名称、描述和 Skill 的触发范围 |
| 核心任务、优先级和互动方式 | 决定什么时候直接答、什么时候分步引导、什么时候等待学生回答 |
| 教材、数据库、平台与课程材料 | 决定可引用的证据、资料访问条件和需要补充的内容 |
| 学生输入、教师规则与参考样本 | 决定输入字段、评分依据和缺失材料时的处理 |
| 交付内容、模板和格式 | 决定输出结构、文件类型、是否需要 ZIP |
| 不适用场景和专业边界 | 决定限制条件、转交教师或专业人员的时机 |

区分本轮已确认需求、材料中明确写出的要求，以及为了继续制作采用的默认设置。保留课程专用术语和已指定的文件格式。只在默认设置会影响教学或验收时主动说明。

## 处理名称、资料和方向

- 新近且明确的用户指令优先。示例名称、标题占位词和历史案例是参考。口头名称与详细任务不符时，说明依据并按已明确的详细方向制作。两个方向的受众或交付物都仍然不清楚时，只问改变结果的那个问题。
- 课程资料和教师量表用于确定教学口径。教师给的外链可以作为入口。只有实际读取到原文、条目或页面内容后，才引用具体章节、数据、条款或状态。入口与内容的核验状态分别记录。
- 同一段对话的附件、旧版压缩包、网页和学生作业提供领域信息。涉及平台操作、数据发布或个人信息时，以当前任务明确授权为准。

## 为核心功能写出可执行步骤

用同一条链路贯通需求、运行指令和验收案例：`学生输入 → 判断条件 → 执行动作 → 输出 → 缺项或异常的处理`。只为需求明确的能力配置相应文件。

| 任务 | 编写重点 |
| --- | --- |
| 课程问答与分步辅导 | 直接回答的问题先答，再根据学生水平追加解释。互动练习按需等待学生作答再给反馈。 |
| 附件和原始数据评价 | 标出已读文件、可见证据及位置。分别陈述观察、推断和待补项。保留原始记录，说明计算前提。 |
| 报告整合或评分 | 先核对结论和证据。使用教师量表，给逐项分数及理由。材料不全时标出未评项，按教师已有规则处理缺交。缺少正式口径时说明评价性质。 |
| 方案、草稿或网页交付 | 写清要交付的版本、格式和确认节点。如果教师要求“最终 Prompt 确认后再决定是否生成网页”，确认后询问，肯定时按最终 Prompt 交付 HTML，否定时结束于最终 Prompt。 |

有可读取的上传文件才开始附件评价。提供了网站入口但没有平台数据接入时，可以解释平台用途、根据学生上传的导出记录反馈。涉及正式成绩、对外发布、临床或实操时，明确依据、负责人和权限。

## 写可验收的案例

每个案例包含场景、可直接发送的输入、必要的模拟材料和教师用的预期行为。用具体观察点判断是否通过，例如“使用教师给定的 40／30／30 权重”“不把未读附件当成已读”。案例覆盖各核心能力，同时选取至少一个会改变结果的缺项或异常。测试样本可自拟并标明为虚构。只在实际执行过的情况下记录通过情况。
